# 조선 야행 1차 개발 계획: 첫 플레이 가능 기반

## 용어 정리

- 수직 기능(Vertical slice): 적은 콘텐츠로 시작부터 승리·패배까지 한 판을 완성하는 방식이다.
- 게임 루프(Game loop): 입력, 이동, 공격, 충돌, 화면 출력을 짧은 간격으로 반복하는 구조다.
- 단일 JVM(Java Virtual Machine): JavaFX 화면과 Spring Boot·Armeria 서버를 하나의 프로그램으로 실행하는 방식이다.
- CI(Continuous Integration): 코드를 GitHub에 올릴 때 빌드와 테스트를 자동 실행하는 검사다.

## 문서 성격

이 문서는 조선 야행의 첫 플레이 가능 버전을 만들기 위해 세운 **1차 계획의 원문 성격을 보존한 기록**이다. 이후 회원·저장소·서버 권위 게임·웹 확장 구조는 [2차 개발 계획](조선-야행-2차-개발계획.md)에서 조정되었으며, 현재 구현과 후속 작업의 기준은 2차 계획이다.

## 핵심 답변

첫 목표는 독자적인 조선 다크 판타지 게임 `조선 야행`의 5분짜리 한 판을 완성하는 것이다. 캐릭터 1종, 자동 공격 무기 1종, 적 1종으로 이동 → 자동 공격 → 경험치 수집 → 레벨업 3택 → 즉사 또는 시간 승리까지 구현한다.

JavaFX·Spring Boot·Armeria는 한 프로세스에서 실행하고, 데이터베이스와 Redis·Kafka·회원·상점은 1차 범위에서 제외한다. 원작의 코드·명칭·이미지·음악은 사용하지 않는다.

## 2. 게임 핵심 구조

- `GameSession`이 플레이어, 적, 투사체, 경험치, 제한 시간, 레벨업 상태를 한 판 단위로 관리한다.
- `GameUseCase`가 새 게임 시작, 입력 반영, 고정 시간 갱신, 보상 선택, 읽기 전용 화면 상태 조회를 제공한다.
- `GameSnapshot`은 JavaFX 렌더러와 Armeria가 안전하게 읽을 수 있는 불변 상태로 제공한다.
- JavaFX의 `AnimationTimer` 안에서 누적 시간을 고정 60Hz 단위로 나누어 계산한다. 화면이 잠시 느려져도 게임 속도가 크게 달라지지 않게 처리한다.

첫 콘텐츠는 다음처럼 고정한다.

- 캐릭터: 도깨비 사냥꾼
- 무기: 가장 가까운 적에게 자동 발사되는 봉인 부적
- 적: 플레이어를 직선 추적하는 그림자 도깨비
- 경험치: 적 사망 시 떨어지는 혼불
- 맵: 경계 없는 달빛 폐허 타일과 플레이어 중심 카메라

게임 규칙은 다음과 같다.

- WASD로 이동하며 대각선 이동 속도를 보정한다.
- 적과 한 번이라도 충돌하면 즉시 패배한다.
- 5분 동안 생성 간격·이동 속도·체력을 단계적으로 높이고, 5분을 버티면 승리한다.
- 레벨업 중에는 시간·적·투사체가 모두 멈춘다.
- 무기 피해량, 공격 주기, 발사체 수, 이동 속도, 경험치 흡수 범위 중 서로 다른 3개 선택지를 제시한다.
- 결과 화면에서 재시작하면 이전 판의 객체·입력·난수 상태가 남지 않게 한다.

## 3. JavaFX·Spring Boot·Armeria·픽셀 아트

- 1280×720 크기의 조절 가능한 JavaFX 창을 사용한다.
- Canvas에는 맵과 전투 객체를 그리고, JavaFX Pane에는 로비·HUD·레벨업·결과 화면을 겹친다.
- FXML과 `module-info.java`는 사용하지 않는다.
- JavaFX `init()`에서 Spring Context와 Armeria를 시작하고 `stop()`에서 모두 종료한다.
- 게임 프레임은 HTTP를 거치지 않고 `game-core`를 직접 호출한다.
- Spring MVC와 Tomcat은 넣지 않고 Armeria 자체 서비스를 사용한다.

초기 내부 API는 다음과 같다.

```text
GET /internal/healthcheck
GET /api/v1/game/status
```

- Armeria는 `127.0.0.1:8080`에만 열고 인증은 넣지 않는다.
- Armeria 스레드는 게임 상태를 직접 변경하지 않고 JavaFX가 발행한 최신 상태 복사본만 읽는다.

자산은 이미지 생성 도구로 조선 야행 스타일의 독자 시안을 만든 뒤 32×32 픽셀 규격으로 정리한다.

- 도깨비 사냥꾼
- 그림자 도깨비
- 봉인 부적
- 혼불
- 폐허 바닥

단색 배경 제거·투명도·격자 크기·최근접 확대 상태를 검수한 최종 PNG만 프로젝트에 넣는다. 이미지 생성 프롬프트와 제작 내역은 자산 문서에 기록하며 원작 이미지는 참조 입력으로 사용하지 않는다.

## 4. 테스트와 완료 조건

- 결정된 난수 시드와 가상 시간으로 이동, 대각선 속도, 자동 조준, 충돌, 적 사망, 경험치 수집, 레벨업 일시정지, 중복 없는 3택, 즉사, 5분 승리, 재시작 초기화를 단위 테스트한다.
- ArchUnit으로 `desktop-app → game-core` 의존 방향과 core의 프레임워크 독립성을 검사한다.
- Spring Context와 Armeria를 임의 포트로 시작해 건강 확인과 상태 API 응답을 통합 테스트한다.
- `./gradlew clean check`와 SpotBugs가 성공해야 하며, GitHub Actions에서도 같은 명령을 실행한다.
- `./gradlew :desktop-app:run` 한 번으로 로비와 서버가 함께 시작되고, 창을 닫으면 프로세스와 포트가 남지 않아야 한다.
- 실제 macOS 창에서 한 판 진행, 레벨업 정지, 즉사, 승리, 재시작과 픽셀 확대 상태를 수동 검증한다.
