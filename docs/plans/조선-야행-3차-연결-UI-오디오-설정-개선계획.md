# 조선 야행 3차 개발 계획

## 목표

실제 플레이에서 4~5초마다 반복되던 WebSocket 재연결을 없애고, Google 로그인·캐릭터 선택·회원별 음향과 화면 프레임 설정을 완성한다. 기존 한 음에 가까운 배경음악은 독자 제작한 로비·전투 반복곡으로 교체하고, 기본·진화 아이템 12종에 공격 효과음을 부여한다.

## 중요한 가정

- REST 요청은 기존 2초 응답 제한을 유지한다.
- 장시간 열려 있어야 하는 WebSocket에는 REST 응답 제한을 적용하지 않는다.
- 서버의 게임 계산은 60Hz, 스냅샷 전송은 약 15Hz를 유지한다.
- 화면 프레임 설정은 JavaFX 전투 Canvas의 다시 그리기 횟수만 제한한다.
- 원작 이미지·음악·효과음이나 외부 샘플을 사용하지 않는다.

## 연결 안정성

- `DesktopApiClient`의 WebSocket 빌더에서 `responseTimeout`을 제거한다.
- REST `WebClient`의 2초 응답 제한과 연결 제한은 유지한다.
- 실제 연결이 끊어졌을 때만 30초 안에 새 일회용 티켓으로 같은 게임 세션에 재접속한다.
- 재접속 중 `START_GAME`을 다시 보내지 않고 입력 순번과 누르고 있던 이동 키를 보존한다.
- 별도 PING/PONG은 이번 범위에 넣지 않는다. 서버가 보내는 게임 스냅샷이 활성 연결 신호 역할을 한다.
- 로그에는 연결 단계와 원인 종류만 남기고 JWT, 티켓, Google 식별값과 게임 세션 식별자를 남기지 않는다.

## Google 로그인 화면

- 달빛 폐허 배경 위에 제목·안내·공식 Google G 아이콘 버튼·개인정보 안내가 분리된 카드를 표시한다.
- 로그인 시 버튼을 잠그고 진행 표시와 `브라우저에서 Google 로그인을 완료해 주세요.` 상태를 보여 준다.
- 실패하면 같은 화면에서 다시 시도할 수 있게 한다.
- 이메일·이름·프로필 사진은 저장하지 않고 보호된 로그인 식별값만 사용한다는 안내를 표시한다.

## 캐릭터 선택

- 콤보박스 대신 전체 캐릭터 카드를 표시한다.
- 카드에는 픽셀 캐릭터, 이름, 설명, 시작 아이템과 고유 스킬을 보여 준다.
- 잠긴 캐릭터도 실루엣과 `잠김` 상태로 표시하되 선택과 게임 시작을 막는다.
- 선택한 해금 캐릭터는 금색 테두리로 구분한다.
- 회원 초기화 API는 각 캐릭터에 식별자, 표시 이름, 설명, 해금 여부, 시작 아이템과 스킬 정보를 반환한다.

## 회원별 설정

설정 계약은 다음과 같다.

```json
{
  "muted": false,
  "musicVolume": 70,
  "effectsVolume": 70,
  "targetFps": "FPS_60"
}
```

- 음량은 Bean Validation으로 0~100을 검사하고 `targetFps`는 필수로 받는다.
- 화면 프레임은 `AUTO`, `FPS_30`, `FPS_60`만 허용한다.
- Flyway V4에서 기존 `master_volume`을 `music_volume`으로 바꾸고 같은 값을 `effects_volume`에 복사한다.
- 기존 회원의 화면 프레임 기본값은 `FPS_60`이다.
- 변경은 0.5초 지연 저장하고 다음 로그인에도 회원별 값을 복원한다.
- 음소거는 모든 소리를 끄며 배경음악과 효과음 음량은 서로 독립적으로 적용한다.

## 배경음악과 효과음

- 로비는 36초 길이의 느린 오음계 선율과 바람·종소리 분위기의 반복곡을 사용한다.
- 전투는 48초 길이의 빠른 선율과 북 장단풍 리듬의 반복곡을 사용한다.
- 두 곡은 22.05kHz, 16비트 스테레오 WAV이며 반복 경계를 부드럽게 만든다.
- 기본 아이템 6종과 진화 아이템 6종에 서로 다른 공격 효과음을 연결한다.
- 다중 투사체도 발사체마다가 아니라 한 번의 공격 묶음마다 효과음 사건 하나만 만든다.
- 효과음 사건은 타입이 명확한 `SoundCue`로 전달하고 사건 ID로 중복 재생을 막는다.
- 같은 효과음이 80ms 안에 반복되면 재생하지 않는다.
- 생성 코드는 `tools/generate_audio_assets.py`, 제작 규격과 파일 목록은 `ASSETS.md`에 기록한다.

## 테스트와 완료 조건

- WebSocket이 REST 제한 시간의 5배 이상 연결된 동안 연결과 티켓 발급이 각각 한 번인지 확인한다.
- 강제 종료 뒤 같은 세션에 한 번 재접속하고 다시 제한 시간의 여러 배 동안 추가 재접속하지 않는지 확인한다.
- 전체 플레이에서 `START_GAME`은 한 번만 보내고 입력 순번과 누른 키를 보존하는지 확인한다.
- 기존 음량이 두 음량으로 보존되는 PostgreSQL Flyway 마이그레이션을 검증한다.
- 누락 설정, 범위 밖 음량과 허용되지 않은 FPS를 거부하는지 검증한다.
- 가상 시간으로 자동·30·60 FPS 제한을 확인한다.
- 전체 캐릭터 반환, 잠금 표시와 잠긴 캐릭터 선택 차단을 확인한다.
- 12종 공격이 공격 묶음당 서로 다른 효과음 사건 하나를 만드는지 확인한다.
- WAV 형식·길이·무음·클리핑·반복 경계를 자동 검사한다.
- macOS에서 로그인, 캐릭터 카드, 로비·전투 음악, 분리 음량, FPS 복원과 60초 연결 유지를 수동 확인한다.
- 최종 순서는 `./scripts/harness run test` → `./scripts/harness run verify` → `./scripts/harness gate`이다.
