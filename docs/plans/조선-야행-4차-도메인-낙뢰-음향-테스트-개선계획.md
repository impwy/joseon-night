# 조선 야행 4차 개발 계획

## 목표

낙뢰 계열 아이템을 이동 투사체가 아닌 적 위치의 즉시 낙뢰로 바꾸고, 독자 합성 음향의 타격감과 선율을 개선한다. 동시에 Lombok 사용 원칙, 애그리거트 경계, 도메인·애플리케이션 검증 책임과 HTTP API 테스트 방식을 코드와 자동 검사로 고정한다.

## 중요한 가정

- 낙뢰형 공격은 `낙뢰 방울`, `천뢰봉인부`, `뇌화신주` 세 종류다.
- 낙뢰 피해는 서버가 공격 순간 확정하고, 화면에는 짧은 시각 상태만 전달한다.
- 공격 수가 둘 이상이면 가까운 서로 다른 적을 거리와 적 식별자 순으로 선택한다. 같은 적에게 중첩 피해를 주지 않는다.
- 제공받은 음원은 음색·타격감·리듬을 이해하기 위한 참고 자료로만 사용한다. 표본과 선율은 복사하지 않는다.
- Lombok은 반복 코드를 줄이는 범위에서 사용하되 `@Data`, 공개 setter와 엔티티 전체 변경 메서드는 사용하지 않는다.

## 낙뢰형 아이템

- `AttackMode`로 이동 투사체와 즉시 낙뢰를 명확히 구분한다.
- 낙뢰 방울과 낙뢰 계열 진화 두 종류는 가까운 적에게 즉시 피해를 준다.
- 낙뢰는 투사체 최대 개수, 속도, 반지름, 수명과 확산 각도의 영향을 받지 않는다.
- 낙뢰 대상 수는 기존 공격 수 강화의 영향을 받지만 서로 다른 현재 적 수를 넘지 않는다.
- 피해·처치 수·혼불 생성은 일반 투사체와 같은 도메인 메서드를 사용한다.
- 공격 묶음마다 효과음 사건은 한 번만 만들고, 대상마다 짧은 `LightningStrikeState` 하나를 만든다.
- 낙뢰 상태는 15Hz 스냅샷 사이에 사라지지 않을 만큼 유지하되 상한을 둔다.
- JavaFX는 적을 그린 뒤 같은 월드 좌표의 머리 위에 청백색 번개와 지면 섬광을 그린다.
- Flyway V5는 이미 적용된 V3를 수정하지 않고 낙뢰 방울 설명을 실제 규칙에 맞게 갱신한다.

## 음향 재설계

- 봉인 부적은 짧고 마른 종이·카드 튕김 질감, 벽사검은 빠른 공기 가르기와 짧은 금속 여운으로 구분한다.
- 낙뢰 계열은 강한 초기 잡음과 낮은 잔향으로 머리 위 직접 타격처럼 들리게 한다.
- 로비와 전투 BGM은 하나의 음을 반복하지 않고 독자적인 오음계 복수 프레이즈, 저음 지속음, 현악·피리풍 합성음과 장단풍 리듬을 조합한다.
- 고정 seed와 Python 표준 `wave`·수학 함수만 사용해 같은 입력에서 같은 WAV를 만든다.
- 22.05kHz, 16비트 스테레오 PCM, 무음·클리핑·길이·반복 경계를 기존 자동 검사로 확인한다.
- 참고 자료는 Freesound의 `swoosh.wav`(CC0), `Dealing Card`(CC BY 4.0), 공유마당의 `국악 배경음악 #55`(CC BY)다. 최종 파일에는 어느 원본 표본이나 선율도 포함하지 않는다.

## Lombok과 애그리거트 경계

- Spring Boot 4.1.0 BOM과 맞는 Lombok 1.18.46을 두 모듈의 컴파일·테스트 애노테이션 처리기에 고정한다.
- 생성자 주입과 단순 접근자처럼 의미 없는 반복만 Lombok으로 줄인다.
- JPA 기본 생성자는 보호 범위를 유지하고, 도메인 setter는 만들지 않는다.
- 다른 애그리거트는 객체 필드가 아니라 `Long`, `String`, `UUID` 같은 식별자 값으로 참조한다.
- 같은 애그리거트 안에서는 객체를 전달할 수 있지만 내부 구성요소의 생성·상태 변경은 애그리거트 루트 메서드를 통해서만 수행한다.
- 회원 애그리거트의 OAuth 식별자·보유 캐릭터·보유 아이템 생성과 로그인 갱신은 `Member` 루트가 담당한다.
- ArchUnit은 서로 다른 도메인 슬라이스의 객체 필드 참조와 내부 구성요소의 공개 변경 메서드를 막는다.

## 검증 책임

- 도메인의 현재 상태에 따른 불변식은 Spring `Assert.state(...)`로 확인한다.
- 값 범위와 논리 조건은 필요한 곳에서 `Assert.isTrue(...)`를 사용한다.
- 외부 요청 형태는 기존 Bean Validation의 `@Valid`, `@NotNull`, `@Min`, `@Max`로 계속 검사한다.
- 저장소 조회가 필요한 중복·존재 검사는 application 슬라이스의 `*ValidationService`로 모은다.
- 애플리케이션 서비스는 검증 결과를 이용해 조율하고, 같은 `if` 검증을 여러 서비스에 흩어 놓지 않는다.

## 테스트와 완료 조건

- 순수 도메인 테스트로 낙뢰 모드, 즉시 피해, 비투사체 규칙, 시각 상태 만료와 결정적 표적 순서를 확인한다.
- 회원, OAuth 식별자, 보유 콘텐츠, 회원 설정, 플레이 기록, Outbox, 캐릭터·스킬·아이템 정의와 진화 불변식을 Spring Context 없이 확인한다.
- 애그리거트 내부 구성요소를 루트 밖에서 변경할 수 없고 다른 애그리거트 객체를 필드로 참조하지 않는지 ArchUnit으로 확인한다.
- `MockMvcTester`로 회원 초기화와 설정 변경의 실제 JSON 성공 응답, 인증 principal, Bean Validation 400 응답을 확인한다.
- PostgreSQL Repository 테스트는 V5 설명과 기존 `flush()`·`clear()` 계약을 확인한다.
- 실제 Core 스냅샷의 낙뢰 JSON을 데스크톱 읽기 모델로 역직렬화한다.
- 생성 스크립트와 Java 오디오 자산 검사가 새 BGM·효과음의 형식, 길이, 무음, 클리핑과 반복 경계를 확인한다.
- macOS에서 낙뢰가 적 머리 위에 표시되고 이동 투사체가 생기지 않는지, 봉인 부적·벽사검 효과음과 로비·전투 BGM이 구분되는지 수동 확인한다.
- 최종 순서는 `./scripts/harness run test` → `./scripts/harness run verify` → `./scripts/harness gate`이다.
